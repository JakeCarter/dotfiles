# Personal Preferences

## Communication
- Be concise by default.
- Explain the reasoning behind non-obvious changes.
- Suggest next steps only when they are clearly useful.
- If are uncertain about something, you should ask clarifying questions.

## Code Style
- Prefer 4-space indentation unless the project already uses something else.
- Imports should be grouped by framework, with groups separated by a blank line. Respect existing groups — don't move them around. When adding an import, place it in the correct group in hess-sort order (@~/.claude/skills/hess-sort/SKILL.md).

## Workflow
- Ask before destructive git operations.
- Do not commit unless I explicitly ask you to.
